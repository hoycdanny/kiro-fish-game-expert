# 機台硬體合規指引

本指引涵蓋實體魚機機台的硬體合規要求：金流裝置、代幣與彩票規格、上下分與後台選單、程式完整性驗證、竄改偵測、必要標示，以及電氣安全與電磁相容認證對應。

若您的部署形態是純線上，本指引大部分不適用，請轉往 `platform-systems-compliance.md`。若是混合部署（同一款遊戲同時有機台版與線上版），兩者都適用，且兩版的數學組態必須各自驗證。

---

## 1. 金流裝置

### 1.1 台灣：最嚴格且最明確的約束

依電子遊戲場業管理條例第 17 條第 1 項第 5 款，機台**不得使用**（信心等級 `HIGH`，讀自條文本文）：

- 真幣
- 信用卡、金融卡、現金卡、儲值卡
- 其他作為簽帳、提款、轉帳或支付之電磁紀錄物或晶片

且娛樂用代幣的**大小、式樣或重量不得與真幣相同或近似**（`HIGH`）。違反者依第 30 條處新臺幣 10 萬元以上 50 萬元以下罰鍰並限期改善（`HIGH`）。

法源：https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=J0080024

**硬體選型後果：**

| 裝置 | 台灣可否使用 | 信心 |
|------|--------------|------|
| 投幣器（收真幣） | ❌ 禁止 | `HIGH`（§17 I ⑤） |
| 鈔票器（收紙鈔） | ❌ 禁止（紙鈔為真幣） | `HIGH`（§17 I ⑤） |
| 代幣投入器 | ✅ 可，但代幣規格受限 | `HIGH`（§17 I ⑤） |
| 讀卡機（信用卡／金融卡／儲值卡支付） | ❌ 禁止 | `HIGH`（§17 I ⑤） |
| 會員卡讀取（僅識別身分，不承載支付功能） | 需確認是否構成「電磁紀錄物」 | `UNVERIFIED` |
| 彩票出票機 | ✅ 可（配合第 14 條的獎品兌換制度） | `HIGH`（§14） |

會員卡是實務上的灰區：若卡片僅儲存會員識別碼、金額記錄在後台系統，是否落入「作為支付之電磁紀錄物」的文義需要當地確認。這一項標記為 `UNVERIFIED`，應在專案早期以書面向主管機關或當地律師確認，因為它會決定整個上下分架構。

### 1.2 其他市場

其他市場的金流裝置要求標記為 `UNVERIFIED`，需依 `jurisdiction-matrix.md` 的查證 SOP 取得。共通的技術要求通常包含：

| 要求 | 說明 |
|------|------|
| 偽幣／偽鈔偵測 | 投幣器與鈔票器需具備並記錄拒收事件 |
| 金流計數器 | 硬體計數器（electromechanical meter）與軟體計數器並存，且可對帳 |
| 錢箱存取記錄 | 開啟錢箱必須記錄時間與存取者 |
| 找零與退幣 | 若提供，需有獨立計數與稽核 |

**硬體計數器與軟體計數器的差異對帳是機台稽核的基本要求。** 兩者不一致是竄改或故障的訊號，必須有告警。

## 2. 代幣與彩票規格

### 2.1 代幣

| 要求 | 說明 |
|------|------|
| 不得與流通貨幣相同或近似 | 台灣為明文要求（大小、式樣、重量） |
| 應具備防偽特徵 | 避免第三方代幣混入造成帳務落差 |
| 代幣價值必須明示 | 在機台與場所明顯處標示投入比例 |
| 代幣不得由場所買回 | 台灣第 14 條禁止買回提供給客人的獎品；代幣買回實質等同兌現 |

### 2.2 彩票（Ticket）

彩票兌換制是魚機在娛樂機具市場的主要兌現形式。技術要求：

| 要求 | 說明 |
|------|------|
| 彩票數量與遊戲結果的對應必須確定且可稽核 | 每次出票事件記錄對應的遊戲事件 |
| 出票機故障處理 | 卡票、缺票、出票不足必須記錄並可補發，補發需有授權紀錄 |
| 彩票價值上限 | 台灣：限制級每次兌換或取得獎品價值上限 NT$2,000，普通級 NT$1,000 |
| 累積彩票的保存 | 若允許存票，需有帳戶或票券機制與對帳 |
| 禁止以彩票兌換現金 | 台灣第 14 條禁止以現金、有價證券或其他通貨為獎品 |

**「每次兌換或取得獎品之價值」的上限是對兌換行為的限制，不是對單次遊戲賠付的限制。** 但實務上若單次遊戲可產生遠超上限的彩票量，兌換環節就會成為法遵瓶頸。建議在數學模型階段就把兌換上限反推為賠付設計約束，見 `math-model.md` 第 2.3 節。

### 2.3 獎品價值的計算基準

台灣第 14 條規定獎品價值以**業者原始進貨發票**為依據。這對供應商的意義是：您無法用「市價」或「建議售價」來主張獎品價值符合上限，場所業者的實際進貨成本才是基準。若您的遊戲設計以特定獎品組合為前提，這個計算基準會影響可行性。

## 3. 上下分與後台選單

### 3.1 上下分（Credit In / Credit Out）

上下分是機台最敏感的功能，因為它直接操作玩家餘額且通常由場所人員執行。

| 要求 | 說明 |
|------|------|
| 需要實體鑰匙或授權碼 | 不得僅靠軟體選單保護 |
| 每次操作記錄操作者身分 | 鑰匙編號、員工代碼或卡片識別 |
| 每次操作記錄前後餘額與金額 | 完整的稽核軌跡 |
| 操作記錄不可就地修改或刪除 | 唯附加日誌 |
| 大額上下分應有二次確認或雙人授權 | 門檻依場所政策，但機制必須存在 |
| 上下分總額必須進入日結對帳 | 與硬體計數器、軟體計數器三方對帳 |

**上下分功能是機台舞弊的主要途徑。** 若您的機台允許無記錄的上分，那台機台在任何受監管環境中都不可能通過稽核，且它同時是場所內部舞弊的工具。

### 3.2 後台選單（Operator Menu）

後台選單通常包含機率設定、賠率表選擇、抽水率設定等項目。這裡是合規審查的重點。

| 項目 | 合規要求 |
|------|----------|
| 進入需實體鑰匙或機門開關 | 不可僅靠密碼 |
| 進入必須記錄事件 | 時間、方式、停留時長 |
| 可調整的數學參數必須全部揭露 | 送測時列出所有可調項與可調範圍 |
| 每個可調組態必須各自驗證 RTP | 不可只送一個組態的 PAR sheet |
| 調整必須記錄前後值 | 唯附加日誌 |
| 調整後應要求重新開機並重新驗證配置雜湊 | 防止熱改參數 |
| **抽水率／回收率設定項** | ⚠️ 若此項的作用是補償式控分，屬架構違規，見 `payout-control-integrity.md` |

最後一項是魚機機台最常見的問題。傳統魚機後台幾乎都有「回收率」設定，其實作往往就是補償控制器。**若該設定的作用是選擇一組不同的固定機率配置（每組各自驗證 RTP），是合規的；若它是動態調節目標，就是違規。** 這個區分必須在送測前釐清。

### 3.3 多組態機台的送測

若機台支援 N 組數學組態（例如 RTP 88% / 92% / 96%），則需要 N 份 PAR sheet，且送測範圍涵蓋全部 N 組。部分市場另有「同款遊戲不得有多個 RTP 變體」的限制，需查 `jurisdiction-matrix.md`。

## 4. 程式完整性驗證

### 4.1 要求

| 要求 | 說明 |
|------|------|
| 關鍵程式與配置需有雜湊值 | 演算法與位元數需符合市場要求（通常至少 SHA-256） |
| 開機時驗證雜湊 | 不符則拒絕進入遊戲並顯示錯誤 |
| 運行期定期重新驗證 | 防止運行期記憶體注入 |
| 雜湊值需可由稽核人員現場讀取 | 通常透過後台選單顯示，供與認證報告比對 |
| 韌體／ROM 更新需有授權與記錄 | 見 `change-management-recert.md` |

### 4.2 台灣：軟體修改視為新型機種

依電子遊戲場業管理條例第 7 條，**機具結構或軟體經修改者，視為新型機種，應即依規定申請檢驗及評鑑分類**；且業者不得陳列、使用未經評鑑分類及公告之機台，或擅自修改已評鑑分類之機台。

違反第 7 條第 1 項者，依第 23 條處負責人或行為人新臺幣 10 萬元以上 50 萬元以下罰鍰。

這使台灣的機台更新不是技術流程而是行政流程。**任何 OTA 更新機制在台灣內銷機台上都是高風險設計**，因為它讓「擅自修改」變得容易且難以證明未發生。

### 4.3 現場稽核的可驗證性

稽核人員到場時需能在不拆機的情況下確認：

1. 機台顯示的程式版本與雜湊值。
2. 該版本雜湊與認證報告／評鑑分類文件一致。
3. 當前生效的數學組態編號。
4. 機具類別標示證與實際機台一致（台灣）。

若這些資訊只能透過拆機或連接開發工具取得，實務上會造成稽核摩擦，並可能被記為缺失。

## 5. 竄改偵測

| 偵測項 | 實作 | 事件處理 |
|--------|------|----------|
| 主機門開啟 | 機門微動開關 | 記錄時間與時長；若非授權期間則告警 |
| 錢箱門開啟 | 獨立開關 | 同上，並與金流對帳關聯 |
| 邏輯板區域開啟 | 獨立開關與封條 | 最高等級告警 |
| 斷電與復電 | 電源事件記錄 | 復電後驗證狀態一致性 |
| 記憶體錯誤 | 校驗碼 | 進入故障狀態，不繼續遊戲 |
| 外接裝置變更 | 週邊列舉比對 | 告警 |

### 5.1 斷電復原

斷電是機台最常見的異常。復電後必須：

1. 驗證程式與配置雜湊。
2. 復原未完成的交易（未完成的扣款或賠付）。
3. 復原玩家餘額到斷電前的一致狀態。
4. 記錄斷電事件與復原結果。

**魚機的斷電復原比老虎機複雜**，因為斷電時桌上可能有多名玩家、多條受傷的魚、進行中的 BOSS 關卡。復原規則必須事先定義：通常是結算所有已完成的捕獲、退還未完成捕獲已投入的成本、清除魚群狀態。無論規則為何，必須確定且揭露，見 `incident-malfunction-handling.md`。

### 5.2 竄改事件的保存

竄改偵測事件必須寫入不可就地修改的儲存，且**在機台軟體被替換後仍然保留**。若竄改記錄與遊戲程式存放在同一個可覆寫區域，記錄本身就可被抹除。

## 6. 必要標示

| 標示 | 說明 |
|------|------|
| 機具類別標示證 | 台灣：由中央主管機關於查驗合格後發給 |
| 營業級別證 | 台灣：由地方主管機關發給，懸掛於營業場所明顯處 |
| 營業級別與入場年齡限制 | 台灣：標示於營業場所入口明顯處 |
| 遊戲規則與賠率表 | 玩家可查閱；魚機必須包含最後一擊或傷害分配規則 |
| 代幣投入比例 | 明示 |
| 獎品兌換規則與價值上限 | 明示 |
| 製造商、型號、序號 | 機台銘牌 |
| 認證資訊 | 依市場要求 |
| 負責任遊戲訊息與求助資源 | 見 `responsible-gaming.md` |

**魚機的遊戲規則標示必須包含多人共享機制。** 最後一擊規則、傷害分配方式、斷線時已投入傷害的處理，這三項若未揭露，在爭議處理與呈現公正性上都是缺口，見 `multiplayer-fairness.md`。

## 7. 電氣安全與電磁相容

這一層與博彩合規分開，屬產品安全法規，但同樣是上市的前提條件。

| 項目 | 一般對應 |
|------|----------|
| 台灣商品檢驗 | 電子遊戲場業管理條例第 6 條第 5 項要求製造業或進口人就機具結構依商品檢驗法申請檢驗 |
| 電氣安全 | 依目的地市場的電氣安全標準（例如歐盟 LVD、北美相關規範） |
| 電磁相容 | 依目的地市場的 EMC 要求 |
| 無線模組 | 若含 Wi-Fi／藍牙，需另有無線電型式認證 |
| 大型機台的機械安全 | 傾倒穩定性、夾點防護、玻璃安全 |
| 座椅與座位安全 | 若機台含座椅 |

魚機機台通常尺寸大、含大面積玻璃或壓克力桌面、多座位，機械安全的檢核項目比直立式機台多。這些項目的認證時程往往與博彩認證平行進行，應在專案排程中一併規劃。

**注意台灣的兩軌制：** 軟體走評鑑分類（第 6 條第 1 項），機具結構走商品檢驗（第 6 條第 5 項）。兩者是不同程序、不同時程，缺一不可。

## 8. 硬體驗收檢查清單

1. 金流裝置符合目標市場限制（台灣：無真幣、無支付卡）
2. 代幣規格不與流通貨幣近似
3. 彩票出票與遊戲事件一對一可稽核，故障可補發且有授權紀錄
4. 硬體計數器與軟體計數器可對帳並有不一致告警
5. 上下分需實體授權，記錄操作者、金額與前後餘額
6. 後台選單需實體授權，進入與調整皆記錄
7. 所有可調數學組態已列舉，每組各有 PAR sheet
8. 後台的回收率設定項已確認不是補償控制器
9. 程式與配置雜湊於開機與運行期驗證
10. 雜湊值與組態編號可由稽核人員現場讀取
11. 機門、錢箱、邏輯板皆有開啟偵測，記錄不可被軟體更新抹除
12. 斷電復原規則已定義並涵蓋多人同桌情境
13. 座位間硬體體感（觸控、按鍵、視角）經驗收無系統性差異
14. 必要標示齊備，含多人共享機制的規則揭露
15. 商品檢驗與電磁相容認證已納入排程

## 9. 需要主動說出的事

1. **台灣機台不能收真幣也不能裝支付卡讀卡機。** 這是硬體選型的第一道約束，不是可以事後調整的細節。
2. **後台的「回收率」設定項通常就是補償控制器。** 這是魚機機台送測最常見的致命傷。
3. **台灣的軟體修改視為新型機種**，需重新檢驗與評鑑分類。OTA 更新機制在台灣內銷機台上是高風險設計。
4. **台灣是軟體評鑑與商品檢驗兩軌並行**，缺一不可，時程需分別規劃。
5. **代幣買回等同兌現。** 台灣明文禁止買回獎品，代幣回收機制需重新設計。
6. **獎品價值以進貨發票為基準**，不是市價，這會影響以特定獎品為前提的設計。
7. **上下分若無記錄，該機台不可能通過任何稽核。**
8. **斷電復原規則必須涵蓋多人同桌**，單人邏輯不夠用。
9. **遊戲規則標示必須揭露最後一擊與傷害分配規則。**
