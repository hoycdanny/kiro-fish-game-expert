# 數學模型驗證與 PAR Sheet 指引（魚機）

本指引涵蓋理論 RTP 計算、技術水準敏感度分析、蒙地卡羅樣本量推導、理論值與模擬值的一致性判定、常見驗證失敗原因，以及魚機 PAR sheet 規格。

魚機的驗證比老虎機難，原因不是數學更複雜，而是**驗證對象多了一個維度**：玩家策略。老虎機驗證一個數字，魚機必須驗證一個策略相依的區間，並證明區間端點都可接受。

---

## 1. 驗證的三個層次

| 層次 | 問題 | 方法 |
|------|------|------|
| 層次 1：理論 | 依模型參數，RTP 應該是多少 | 解析計算，每發子彈期望回收 |
| 層次 2：模擬 | 實際程式跑出來是多少 | 蒙地卡羅，以真實判定程式碼執行 |
| 層次 3：策略 | 不同技術水準的玩家分別拿到多少 | 多策略代理人模擬 |

三個層次都必須產出數據。只做層次 2 是最常見的不足——它證明程式沒寫錯，但不證明模型正確，也不回答監管機關關於技術成分的問題。

---

## 2. 層次 1：理論 RTP 計算

### 2.1 每魚種期望回收率

以生命值扣減加隨機傷害模型（`math-model.md` 模型 C）為例：

```
期望子彈數_i = 生命值_i / E[每發傷害]
期望回收率_i = 賠率倍數_i × E[每發傷害] / 生命值_i
```

### 2.2 加權合成

```
基礎魚種 RTP(策略 s) = Σ_i [ w_i(s) × 期望回收率_i ]
```

其中 `w_i(s)` 是策略 s 下打向魚種 i 的子彈比例，且 `Σ w_i(s) = 1`。

**這是魚機理論計算的核心：權重來自策略，不來自遊戲配置。** 因此理論 RTP 不是單一值。至少計算三組權重：

| 策略 | 權重定義 |
|------|----------|
`w_random` | 依魚種在畫面上的面積比例分配（等同無瞄準能力的隨機射擊） |
`w_typical` | 依實測玩家行為資料分配；無資料時以「偏好中大型魚」的合理假設並註明為假設 |
`w_optimal` | 全部子彈投向期望回收率最高的魚種（考量命中率後的實際最優） |

### 2.3 加上其他層

各層 RTP 貢獻依 `math-model.md` 第 5 節計算後加總。特殊武器與 BOSS 的貢獻同樣是策略相依的，必須在三種策略下分別計算。

### 2.4 命中率的併入

上式的「期望回收率」假設子彈命中目標。實際上：

```
實際 RTP(策略 s, 命中率 h) = h(s) × 基礎期望回收率(s) + 其他層貢獻
```

`h(s)` 是該策略下的命中率。隨機瞄準的命中率可能只有 30%，熟練玩家可達 85% 以上。**命中率是技術跨距的主要來源，且它是乘法項，影響非常大。**

這帶出一個關鍵設計問題：若命中率完全由技術決定且跨距很大，則熟練玩家的 RTP 可能遠高於 100%。實務上必須用魚體碰撞範圍與魚群密度設計，讓命中率有實際上限（例如高密度小魚使隨機射擊也有相當命中率，同時大魚體積使命中率天花板不至於過低），把技術跨距壓在可控範圍。

## 3. 層次 2：蒙地卡羅模擬

### 3.1 必須以真實判定程式碼執行

模擬不得用另寫的簡化版數學。必須呼叫產品實際的捕獲判定、傷害計算與賠付結算程式碼，只把渲染與網路層抽換掉。用簡化版模擬得到的一致性沒有證據價值——它證明的是兩份數學一致，不是產品正確。

### 3.2 樣本量推導

不要用「跑一千萬發」這種產業口耳相傳的數字。從目標精度反推：

```
n ≥ (z × σ / ε)²
```

- `ε`：可接受的 RTP 絕對誤差（例如 0.1 個百分點 = 0.001）
- `σ`：單發子彈回收率的標準差，**必須先用試跑量測，不可假設**
- `z`：信賴水準對應值（95% → 1.96）

魚機的 `σ` 比老虎機大得多，因為單發子彈的回收極度偏態（絕大多數為零，少數為賠率倍數的整數倍）。含 ×500 BOSS 的高波動配置，`σ` 可能達到 5 以上。

**範例：** 若量測 `σ = 4.5`，目標 `ε = 0.001`，95% 信賴水準：

```
n ≥ (1.96 × 4.5 / 0.001)² ≈ 7.78 × 10⁷
```

約需 7,800 萬發子彈。若配置含更高倍數的 BOSS，需求可達數億發。

### 3.3 BOSS 與稀有事件需分層抽樣

若 BOSS 關卡的進入頻率是每 10 萬發一次，7,800 萬發只包含約 780 次 BOSS 事件，不足以精確估計 BOSS 層的 RTP 貢獻。做法：

1. 主模擬估計基礎層與武器層。
2. **對 BOSS 層另做專門模擬**，直接強制進入關卡數十萬次，估計關卡期望賠付。
3. 以理論進入頻率合成 BOSS 層 RTP 貢獻。
4. 在文件中說明分層抽樣方法與各層樣本量。

同樣做法適用於跨桌獎池與極稀有魚種。

### 3.4 多人同桌的模擬

魚機的 RTP 在單人模擬中可能與多人情境不同，因為同桌玩家會搶奪同一批魚。必須模擬：

| 情境 | 目的 |
|------|------|
| 單人滿桌魚 | 上界情境 |
| 滿座（8 人）同時射擊 | 魚被搶走導致的期望值變化 |
| 混合技術水準（1 名熟練 + 7 名隨機） | 熟練玩家是否從其他座位「吸取」期望值 |
| 兩名熟練玩家針對同一批大魚 | 搶魚導致的期望值稀釋 |

**若某個座位的 RTP 依賴其他座位的行為，這件事必須揭露。** 這不一定違規，但它是實驗室與監管機關會問的問題，沒有預先分析會導致送測停滯。

## 4. 層次 3：技術水準敏感度分析

### 4.1 代理人設計

建立至少四種代理人，各自獨立模擬：

| 代理人 | 瞄準 | 目標選擇 | 道具使用 |
|--------|------|----------|----------|
| A：隨機 | 隨機角度 | 隨機 | 不使用 |
| B：新手 | 直接對準當前位置（不算提前量） | 偏好大魚 | 取得即用 |
| C：典型 | 含提前量，中等精度 | 偏好中型魚 | 取得後短暫等待 |
| D：最佳 | 完美提前量 | 期望回收率最高魚種 | 最佳時機 |

### 4.2 產出表格

| 代理人 | 命中率 | 基礎 RTP | 武器 RTP | BOSS RTP | 總 RTP |
|--------|--------|----------|----------|----------|--------|
| A：隨機 | — | — | — | — | — |
| B：新手 | — | — | — | — | — |
| C：典型 | — | — | — | — | — |
| D：最佳 | — | — | — | — | — |
| **技術跨距（D − A）** | | | | | **—** |

### 4.3 判讀規則

| 觀察 | 含義 | 行動 |
|------|------|------|
| 技術跨距 < 2 個百分點 | 玩家操作實質上不影響期望值 | 技術性主張不成立；若市場依賴此主張，設計需重做 |
| 技術跨距 2–10 個百分點 | 技術有影響但機率仍可能佔優 | 可作為論據，但預期會被挑戰；需完整卷宗 |
| 技術跨距 > 10 個百分點 | 技術影響顯著 | 檢查代理人 D 的 RTP 是否超過 100%（營運風險） |
| 代理人 D 的 RTP ≥ 100% | 熟練玩家可長期獲利 | 必須調整；通常透過壓低命中率天花板或縮小魚種期望回收率差距 |
| 代理人 A 的 RTP 低於市場最低派彩率 | 最不熟練的玩家低於法定門檻 | 高風險。多數市場的門檻適用於所有玩法，不是平均值 |

最後一列是魚機特有且容易被忽略的合規風險：若市場規定最低派彩率 X%，而隨機策略玩家實測只有 X−5%，那麼「平均 RTP 達標」的辯解在多數條文文義下站不住。應在送測前確認實驗室對此的立場。

## 5. 一致性判定

### 5.1 判定準則

比較理論值與模擬值，兩者差距應落在模擬的 95% 信賴區間內：

```
|RTP_理論 − RTP_模擬| ≤ 1.96 × σ / √n
```

若超出，**不要調整理論值去迎合模擬值**，也不要增加樣本量直到通過。差距是實作與模型不一致的訊號，必須找出原因。

### 5.2 魚機常見的驗證失敗原因

| 現象 | 常見原因 |
|------|----------|
| 模擬 RTP 系統性低於理論值 | 傷害計算使用整數截斷（`floor`），使實際期望傷害低於名目值 |
| 模擬 RTP 系統性高於理論值 | 特殊武器 RTP 貢獻的分母用了觸發當下的單發成本，而非取得成本 |
| 各砲倍 RTP 不一致 | 傷害或捕獲機率隱含依賴砲倍；或最低傷害保底在低砲倍時生效比例不同 |
| 高砲倍 RTP 偏低 | 存在單次賠付上限但未計入理論值 |
| 模擬 RTP 隨模擬時長漂移 | 存在補償式控分或任何歷史相依邏輯（`payout-control-integrity.md`） |
| 多人模擬 RTP 低於單人 | 魚被搶走導致命中未捕獲的子彈比例上升；需確認是否為預期設計 |
| 魚離場導致的損失未計入 | 已扣血但未捕獲的魚游出畫面，投入的子彈成本無回收 |
| BOSS 層估計不穩 | 樣本量不足，未做分層抽樣 |
| 場景切換時狀態重置 | 魚群重置使已投入的傷害歸零，構成未計入的損失 |

最後兩項是魚機特有且金額影響顯著的漏項。**已對某條魚投入的子彈成本，若該魚離場或場景重置，是純損失。** 這部分若未計入理論模型，理論 RTP 會系統性高於實際。

### 5.3 稀有事件的信賴區間

BOSS 與最高倍魚種的 RTP 貢獻估計的信賴區間應單獨報告，不要只報總 RTP 的區間。若 BOSS 層貢獻 3.0% 但其 95% 區間是 [1.8%, 4.2%]，那麼總 RTP 96% 的實際不確定性遠大於總量區間所顯示的。

## 6. 魚機 PAR Sheet 規格

PAR sheet（Probability and Accounting Report）是送測的核心數學文件。魚機版需要老虎機版沒有的章節。範本：`templates/certification/par-sheet.json`。

| 章節 | 內容 | 魚機特有 |
|------|------|----------|
| 1. 遊戲識別 | 名稱、版本、建置雜湊、雜湊演算法位元數 | |
| 2. 遊戲形態 | 部署形態、座位數、桌型拓撲、兌現模式 | ✓ |
| 3. 投注單位定義 | 明確聲明以一發子彈為投注單位及其理由 | ✓ |
| 4. 魚種賠率表 | 逐魚種：賠率倍數、生命值、池中數量、畫面面積比例 | ✓ |
| 5. 捕獲機率模型 | 模型類型、傷害分佈、期望子彈數、期望回收率 | ✓ |
| 6. 砲倍配置矩陣 | 每一砲倍的單發成本、理論 RTP、最高單次賠付 | ✓ |
| 7. 特殊武器 | 取得條件、累積成本、機制、RTP 貢獻與分母說明 | ✓ |
| 8. 場景與 BOSS | 輪替規則、進入頻率、關卡期望賠付、分配規則 | ✓ |
| 9. 跨桌獎池 | 抽取比例、層級、觸發條件、封頂與回收處理 | |
| 10. RTP 構成拆解 | 逐層貢獻，在三種策略下各一份 | ✓ |
| 11. 技術水準敏感度 | 四代理人表格與技術跨距 | ✓ |
| 12. 體感命中率 | 產生賠付的子彈比例，以及命中未捕獲比例 | ✓ |
| 13. 波動性指標 | 單發回收標準差、最高賠付機率、破產風險曲線 | |
| 14. 多人情境分析 | 單人／滿座／混合技術水準下的 RTP 差異與座位間公平性 | ✓ |
| 15. 損失項揭露 | 魚離場、場景重置、未完成捕獲導致的未回收成本 | ✓ |
| 16. 模擬方法 | 樣本量推導、量測 σ、分層抽樣說明、一致性判定結果 | |

### 6.1 最容易被遺漏的三節

1. **第 3 節投注單位定義。** 沒有這一節，後續所有 RTP 數字都缺少解釋基礎，實驗室會退回。
2. **第 6 節砲倍配置矩陣。** 必須列出**所有**砲倍，不是抽樣。各砲倍 RTP 必須相同。
3. **第 15 節損失項揭露。** 這是魚機獨有且最常漏的一節，也是理論與模擬不一致的最常見來源。

### 6.2 建置綁定

PAR sheet 必須綁定特定建置雜湊。任何影響數學的變更都會使該份 PAR sheet 失效，見 `change-management-recert.md`。

## 7. 驗證流程

1. 完成模型設計，產出理論 RTP（三種策略）
2. 建立以真實判定程式碼驅動的模擬框架
3. 試跑量測單發回收率標準差 σ
4. 依目標精度推導樣本量
5. 執行主模擬，取得層次 2 數據
6. 對 BOSS、跨桌獎池、極稀有魚種執行分層抽樣模擬
7. 執行四代理人技術水準敏感度分析
8. 執行單人／滿座／混合技術水準的多人情境模擬
9. 執行一致性判定；若不通過，依第 5.2 節排查，修正實作或模型後回到步驟 5
10. 驗證各砲倍 RTP 完全一致
11. 檢查代理人 A 的 RTP 是否達到目標市場最低派彩率門檻
12. 檢查代理人 D 的 RTP 是否低於 100%
13. 產出 PAR sheet，綁定建置雜湊

---

## 8. 需要主動說出的事

1. **不要用產業慣用的樣本量數字。** 魚機的單發回收變異遠大於老虎機，一千萬發對高波動配置遠遠不足。
2. **模擬必須用產品的判定程式碼。** 另寫一份簡化數學來模擬，證明力等於零。
3. **只報一個 RTP 數字的 PAR sheet 不完整。** 魚機必須報策略相依區間。
4. **最不熟練玩家的 RTP 也要達標。** 多數最低派彩率條文的文義不是「平均達標」。
5. **檢查最佳策略是否超過 100%。** 這是營運存亡問題，不只是合規問題。
6. **模擬 RTP 隨時間漂移就是控分。** 這是最嚴重的發現，應立即中止其他討論處理它。
7. **損失項必須揭露。** 魚離場與場景重置造成的未回收成本若不計入，理論 RTP 一定偏高。
